# Configuration and boundaries

Set `ARCTURION_BRAIN_WORK_ROOT` to an absolute directory you control before importing the engine. Its working paths are derived from that root. Review the remaining module configuration and file access before using real material: this source edition is not a tenant-isolation or authorization boundary.

Set `ARCTURION_BRAIN_POLICY_PATH` to an absolute path to a caller-owned JSON policy. Required keys are `excluded_agents` (object mapping names to reasons), `skip_path_fragments` (list of nonempty strings), `privacy_topic_pattern`, `privacy_person_pattern`, `privacy_path_marker` (nonempty strings), and `restricted_recovery_root`, `legacy_protected_root` (absolute paths). Supply appropriate exclusions and patterns for your own material; empty collections mean no exclusions. See [example-policy.json](example-policy.json) for an invented template; change its paths and policy to suit your deployment. The synthetic proof writes its own invented policy. This configuration is not a complete privacy guarantee. Optional host integrations require their own configuration and have not been verified by this proof. Ownership-aware integrations require `ARCTURION_BRAIN_OWNER_NODE_ID`; optional command and hook paths can be configured using `ARCTURION_BRAIN_PROVIDER_CLI`, `ARCTURION_BRAIN_REMINDERS_CLI`, and `ARCTURION_BRAIN_POLICY_HOOK_ROOT`.

Vector seeding is disabled by default. The local model path is explicitly configured with `ARCTURION_BRAIN_LOCAL_MODEL`; the model and its dependencies are not included or tested here. Optional integrations may need additional libraries and platform permissions. Do not assume that installing the core requirements enables them. The graph viewer loads browser libraries from external CDNs; its dependencies and behavior need separate review before use.

`guarded_proof.py` uses invented files and a fresh direct child work directory. Its Python audit hook is a guard for the inspected proof, not an operating-system sandbox: native code, metadata operations, directory-relative paths and inherited descriptors are outside its guarantees. It exercises local in-process HTTP and MCP dispatch, not a running server. The directed example edge is inserted explicitly. The inherited original test suite requires additional fixtures and is not the default release check.

Answer judging and its asynchronous worker are disabled by default. An operator who enables both `ARCTURION_BRAIN_ANSWER_JUDGE=1` and `ARCTURION_BRAIN_ANSWER_JUDGE_ASYNC=1` and supplies an absolute executable in `ARCTURION_BRAIN_CODEX_BIN` enables external judging. Eligible questions and journal title, path, summary and excerpts may be sent to that provider; provider usage may incur cost. Review the records and provider terms before enabling it. The separate supersession judge also requires that explicit executable.

## Optional corpus rules

The VEGA corpus adapter uses `ARCTURION_VEGA_RULES_PATH`, an absolute path to a caller-owned JSON file, for deployment-specific grounded rules and source-bound pins. The command interface also accepts `--rules` before its subcommand. The [loader](engine/vega_corpus.py) documents the required `grounded` and `pins` lists; private rules, source quotes and source digests are not bundled.

Without configuration, these optional rules are unavailable. An index previously synchronized with configured rules refuses another synchronization if that configuration disappears. To intentionally withdraw the rules, supply an explicit file containing `{"grounded": [], "pins": []}`. Review your configuration and source material before enabling extraction.
